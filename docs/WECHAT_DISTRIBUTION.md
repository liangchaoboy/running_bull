## 1. 结论摘要

**今天就能做的主路径：把 `mobile-web/` 部署到国内可访问的 HTTPS 静态托管，再在微信内投链接 + 二维码（社群 / 1v1 / 朋友圈）。**  
不要用 `x.qiniu.com` 当手机入口。自托管静态 H5，不是微信小游戏；部署后微信内打开、扫码均可，无需迁引擎、无需小程序主体。

| 排序 | 路径 | 栏位 | 一句话 |
| --- | --- | --- | --- |
| **1** | 微信群 / 1v1 发链接 + 二维码 | 今天就能做 | 零资质，马上引流试玩 |
| **2** | 朋友圈发链接 / 海报二维码 | 今天就能做 | 注意外链规范，禁诱导分享 |
| **3** | 公众号图文 / 菜单 / 自动回复 | 要资质 | 有号就能投；认证后菜单更稳 |
| 4 | 企业微信客户群 / 活码 / 获客链接 | 要资质 | 有企微主体再上规模 |
| 5 | 小程序 web-view 包一层 H5 | 要资质 | 非个人主体 + 业务域名；`x.qiniu.com` 校验文件大概率放不了 |
| 6 | 视频号挂链 | 要资质 / 能力受限 | **不能直接挂 H5**；最多挂关联公众号文章 |
| 7 | 原生微信小游戏 | 要迁引擎 | 后续路径；与 XBuilder 鸿沟大，不抢今天 |

**今天第一步（任何人）：**  
部署 `mobile-web/` 拿到 HTTPS 地址 → 用微信打开确认能玩 → 生成二维码 → 发到 1 个种子群，附下方「社群话术」。

**需 Vincent 拍板的前提：**

1. 是否已有**公众号**（订阅号 / 服务号）？是否已认证？  
2. 是否已有**企业微信**主体与客户联系能力？  
3. 是否计划申请**非个人主体小程序**（仅为 web-view 包壳）？  
4. 原生小游戏是否纳入 1024 后排期（软著 / 备案 / 引擎迁出）？

## 5. 小程序 web-view 包一层是否可行

### 结论

**可行性：有条件可行，但对《勇敢牛牛》当前试玩域，实操大概率卡住。**  
更适合作为「有自有备案域名之后」的增强，**不是今天路径。**

### 硬性条件（官方）

来源：  
- https://developers.weixin.qq.com/miniprogram/dev/component/web-view.html  
- https://developers.weixin.qq.com/miniprogram/dev/framework/ability/domain.html  
- https://developers.weixin.qq.com/doc/oplatform/developers/basic_func/domain  

| 条件 | 要求 |
| --- | --- |
| 主体 | **非个人**小程序；个人主体不支持 web-view / 业务域名 |
| 业务域名 | HTTPS；ICP 备案；根目录放置校验文件；管理员扫码确认 |
| 数量 | 每账号最多约 300 个业务域名 |
| 内容 | 内嵌页须备案；服务须与小程序类目一致；不得用 web-view 规避小程序规则 |
| 小游戏账号 | 业务域名/web-view **不对小游戏账号开放**（勿用游戏类目号做壳） |

### 与 XBuilder 的冲突点

1. 试玩在 `x.qiniu.com`（七牛 XBuilder 平台域）。  
2. 配置业务域名必须在**该域名根目录**放微信校验文件。  
3. 团队通常**不能**在七牛平台根域写文件 → **无法完成校验**（除非七牛提供白名单/代配能力，**需再核** XBuilder / 七牛文档或工单）。  
4. 变通：自有备案域名反代到试玩页 → 在自有域放校验文件 → 再配业务域名。工作量与运维成本高于「直接投 H5」。

### 何时值得做

- 已有企业主体小程序（非游戏类目），需要「小程序码」分发、或要嵌在已有小程序流量里。  
- 已有自有备案域名并可反代。  
- 否则：**直接投 H5 更优。**

## 6. 若上微信小游戏：真实步骤、主体、鸿沟、工期

### 6.1 关键前提

- XBuilder Publish = **H5**，**不是**微信小游戏包。  
- 官方「通用引擎适配」面向 **WASM + WebGL** 的 `.js` / `.wasm` / `.data` 产物 + `wx-transformer` 转换。  
  - https://developers.weixin.qq.com/minigame/dev/guide/game-engine/common-adaptation  
- spx / XBuilder 教育向 H5 栈是否导出符合上述产物：**当前无官方一键「导出微信小游戏」可依赖 → 存在引擎鸿沟**，需 1024 / 产研评估（重做、换引擎、或等平台能力）。

### 6.2 主体与资质（门槛）

| 项 | 说明 |
| --- | --- |
| 注册 | 微信公众平台注册小程序，服务类目选 **游戏**（选定后**不可**改回普通小程序类目） |
| 认证 | 企业主体须微信认证后才能提交小程序备案 |
| 备案 | 上线前必须完成小程序备案 |
| 审核 | 版本审核 + 资质材料（软著、自审报告、隐私协议等，以当次提审清单为准） |
| IAA（广告） | 相对可走；仍要过审与备案；流量主另有门槛 |
| IAP（内购） | 企业主体 + **游戏版号**等法定资质，周期长；本报告不展开变现 |

发布时效参考（官方，会变）：不开通虚拟支付约 13–37 工作日；开通虚拟支付约 9–22 工作日（含并行项）。  
https://developers.weixin.qq.com/minigame/introduction/guide/

运营红线：小游戏内须提供完整服务，**不得**引导用户到 H5/App 才玩完整版。  
https://developers.weixin.qq.com/minigame/product/

### 6.3 迁出 XBuilder 的大致步骤（产研向）

1. **可行性评估（3–10 天）：** 确认 spx 运行时能否产出 WASM+WebGL；音视频、输入、存储 API 差距表。  
2. **主体与材料并行：** 企业认证、软著申请、隐私协议、备案材料。  
3. **技术迁出（最大不确定性）：**  
   - 若可导出 WASM 包 → 走 `wx-transformer` → 微信开发者工具 → 配 CDN 安全域名 → 性能调优 / Wasm 分包。  
   - 若不能 → 换受支持引擎重制，或维护双端（H5 继续 XBuilder + 小游戏独立工程）。  
4. **提审与备案：** 上传体验版 → 真机 → 提审 → 备案完成 → 全量发布。  
5. **上线后：** 合规运营；不要反向导流回 H5 完整玩法。

### 6.4 工期粗估（日历，非承诺）

| 场景 | 粗估 |
| --- | --- |
| 仅行政（认证+备案+材料）并行 | 约 2–6 周 |
| 技术可走通用 WASM 转换且游戏简单 | 约 3–8 周（含调优提审） |
| 需换引擎 / 重制 | **数月**；与 1024 排期绑定 |
| 含 IAP / 版号 | 另计，常以月～年计 |

**建议：** 今天用 H5 引流验证；原生小游戏单独立项，不阻塞试玩。
